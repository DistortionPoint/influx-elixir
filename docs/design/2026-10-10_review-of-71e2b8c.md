# Review of 71e2b8c: Flight defaults, per-server escapes, Flight timeouts, raises

**Date**: 2026-10-10
**Scope**: `Flight.Reader`, `Flight.Client`, `Write.LineProtocol`, `Write.Point`, `Write.BatchWriter`, `Connection`, `Client.HTTP`, `Client.QueryParams`, `InfluxElixir`, `Client.Local` (v2 line-protocol unescape)
**Issue**: review of 71e2b8c (findings F1, F2, F3 encoding part, F6, F8, F10)
**Supersedes**: none

---

## Problem

Each defect was reproduced before it was changed, against InfluxDB 3 Core 3.10.1 (`localhost:8181`) or
InfluxDB 2.7.12 (the one-liners in `README.md`).

### F1: Flight reads FlatBuffer defaults as if they were set

FlatBuffers leave out a field that holds its schema default, and `Schema.fbs` defaults `Int.is_signed`
and `Int.bitWidth` to 0/false and `FloatingPoint.precision` to HALF. The reader had `is_signed`
absent = signed and precision absent = double.

| Statement | HTTP | Flight before |
|---|---|---|
| `arrow_cast(200,'UInt8')`, `60000` UInt16, `3000000000` UInt32, `10000000000000000000` UInt64 | 200, 60000, 3000000000, 10000000000000000000 | -56, -5536, -1294967296, -8446744073709551616 |
| field `u=18446744073709551615u` | 18446744073709551615 | -1 |
| `arrow_cast(1.5,'Float16') a, 2 c` | `a` = 1.5, `c` = 2 | `[%{"c" => 2}]` (the column dropped) |

The audit of every other FlatBuffer read: the Timestamp unit (absent = second), Duration unit (absent =
millisecond), Date unit (absent = millisecond, Date64), Decimal `bitWidth` (absent = 128; scale and
precision 0), FixedSizeList `listSize` (0), Field `type_type` (NONE), dictionary, children and the
Message header type were already right, and are now commented as defaults. The audit found two more
differences from HTTP, both fixed:

- A Float32 (and Float16) is printed by HTTP as the shortest decimal that reads back as the same 32
  bits (`0.1`); Flight gave the double of the bits (`0.10000000149011612`).
- A Date64 is a datetime string over HTTP (`1970-01-02T00:00:00.500`, which `ResponseParser` reads as
  a `DateTime`); Flight gave a date. An infinity or a NaN is `null` over HTTP (a key that is present,
  where a null cell has no key); Flight dropped the cell and, for a Float64, shifted the values after
  it (a comprehension skips what a float pattern does not match).

### F2: `\\` is one backslash on InfluxDB 3 and two on 2.7

`LineProtocol.encode` escaped a backslash in measurements, tag keys and values and field keys. InfluxDB 3
reads `\\` as one backslash (12 strings round-tripped on Core); 2.7's parser never unescapes it in a
name. Tag value `a\b` was stored on 2.7 as `a\\b`. 25 strings in five positions (measurement, tag key,
tag value, field key, string field value) were written to 2.7.12 and read back through Flux:

- 2.7 undoes a backslash only before a character the position escapes: in tag keys and values `,` `=`
  and space; in measurements and field keys those and `"`. A backslash before any other character, or
  before another backslash, is kept as written.
- A measurement written with `\=` or `\"` is stored (`schema.measurements` lists it) but no
  `range()` query returns its points, and plain `=` or `"` in a measurement works. So a measurement
  escapes only `,` and space.
- A measurement with a backslash before `,`, space, `=` or `"`, and a field key with one before `,`,
  space or `=`, cannot be kept: the points are unqueryable, or the write is a 400 (`invalid field
  format`, the scanner takes `\\` as a pair and the next `,` as the end of the field set). No encoding
  of those names reads back as written.
- A string field value escapes `\` and `"`, as on v3.

`Client.Local`'s `:v2` table (`LineProtocolEscape`) already matched all of it: the same 25 × 5 strings
gave the same answers on 2.7 and on Local.

### F3 (encoding): `Point.new` and `LineProtocol.encode` raised

`Point.new("m", f, tags: nil)` and `Point.new("m", nil)` raised in `Enum.sort_by(nil)` or `map_size(nil)`;
`encode(:x)`, `encode([%{}])` and `encode(point, :notkw)` raised.

### F6: Flight `:timeout` was a request header

A TCP peer that accepts and stays silent held `Flight.Client.query/3` for the gRPC library's wait (5 s;
60 s until the peer closed), whatever `:timeout` said. `Client.HTTP` passed only the call's `:timeout`,
never the connection's. A failed query was a `%GRPC.RPCError{}`, where HTTP gives
`%{status: _, body: _}`. An empty token sent `Authorization: Bearer `. The ticket payload was built
twice.

### F8: HTTP and `QueryParams` raised on what a caller passes

No Finch pool of that name: `ArgumentError: unknown registry`; a keyword connection without `:name`
or `:finch_name`: `KeyError`; a parameter that is an improper list or has a tuple map key: Jason
raised; `InfluxElixir.query_sql("hostname", ...)` raised in the telemetry span (`"hostname"[:database]`);
`query_influxql(..., format: nil)` sent `"format": ""` and got a 400.

### F10: Local's v2 unescape was quadratic

`unescape_v2/3` rebuilt `<<c, rest::binary>>` for each backslash before a character that is no escape,
copying the rest of the text: 200,000 of them (a `\x` repeated in one tag value) took 1.05 s.

## Design

- **Reader.** `resolve_type_id` reads `bitWidth` absent as 0, `is_signed` absent as false, and
  `precision` absent as HALF, which has no type id and decodes as the `:float16` kind. Half precision is
  decoded from its bits (sign, 5-bit exponent, 10-bit fraction; subnormals as fraction × 2^-24; exponent 31
  is infinity or NaN). Float16 and Float32 go through `shortest32/1` (the fewest digits, 1 to 9, that
  read back as the same 32 bits). An infinity or NaN cell is the atom `:non_finite` until `zip_columns/3`
  writes it as `nil`, and inside a list as `nil`. Float64 columns keep the single-pass comprehension and
  are read again by bits only when it skipped a cell. Date64 is a `DateTime`.
- **LineProtocol.** `encode/2` takes `api_version: :v3 | :v2` (default `:v3`); it validates its options and
  its argument first and answers `{:invalid_options, opts}` / `{:invalid_point, term}`. Escape kinds per
  dialect are a table (`@kinds`); the names 2.7 cannot keep are listed beside it, per position
  (`measurement_refuses`, `field_key_refuses`), and refused with the existing error shapes. The alternative,
  writing them anyway, stores different text silently on a `204`. `BatchWriter` reads the connection's
  `api_version` per `Point` through the new `Connection.api_version/1` (a name, a keyword list or a
  `Client.Local` connection).
- **Point.new.** `nil` fields and tags are empty (the spec says so).
- **Flight.Client.** The call and the collecting of its stream run in one monitored, unlinked process
  (the adapter delivers the stream to the process that made the call) under the generalised `bounded/4`,
  also used by `bounded_connect/2`; past `:timeout` it is killed and the answer is `{:error, :timeout}`,
  and the channel is closed by the caller. A gRPC error is `%{status: http_status, body: message}`:
  3 → 400, 16 → 401, 7 → 403, 5 → 404, 6 → 409, 8 → 429, 12 → 501, 14 → 503, 4 → `:timeout`, others 500. Verified with the same
  statements over both transports on Core: a syntax error, an unknown table, an empty statement and DDL
  are 400 on both; a schema error (`SELECT nosuch FROM m`) is 500 over HTTP and gRPC 3 (400) over Flight; a
  database that does not exist is 404 over HTTP and gRPC 13 (500) over Flight; Flight's message keeps
  `Error while logically planning query: `. The 401 and 403 are the standard mapping (no Core with auth was
  started for this review). Those differences are in the docs of `query_sql/3`, not hidden. `Client.HTTP`
  passes `resolve_timeout/2` (the call's, else the connection's) to Flight. `build_ticket/2` and
  `build_ticket_payload/2` stay: they are public and documented.
- **Client.HTTP / QueryParams / facade.** `resolve_finch/1` returns `{:ok, name} | {:error, :no_pool_name}`;
  `do_request/6` and the streaming producer rescue `ArgumentError` (`unknown registry` is `:no_pool`) as
  they rescued `RuntimeError`. `encodable/2` rescues what `json_body/1` rescues. `query_span` answers
  `{:invalid_connection, term}` for a connection that is neither a keyword list nor a map. `format: nil`
  is `:json` for SQL and InfluxQL.
- **Local.** The fallback clause of `unescape_v2/3` continues with the binary after the backslash, which
  is a sub-binary and copies nothing.

## Verification

The fixtures were captured from Core with a throwaway script (not kept): for each statement, the Flight
frames (`FlightService.Stub.do_get` on `localhost:8181`, each `FlightData` as `%{data_header:, data_body:}`)
and the HTTP rows (`POST /api/v3/query_sql`, `format: json`) go into a map `%{sql:, http_rows:, frames:}`
written with `:erlang.term_to_binary/1`, the format of the existing `.etf` files. Each decodes to
the HTTP rows after `ResponseParser.coerce_types/1` (checked with `===`), which is the loop in
`reader_fixtures_test.exs`. The fixtures cover UInt8/16/32/64 (including values past 2^63), Float16 (a
subnormal, the largest, `-0.0`, infinity, NaN), Float32 (infinity), lists and structs of them, and
Date64.

The 125 round trips of F2 ran on 2.7.12 and on `Client.Local` (`:v2`): 101 stored and read back as
written, 24 refused by the encoder as above; the same values on both. `unescape_v2` before and after:
200,000 `\x` pairs in one tag value, 1050 ms and 42 ms. The silent peer, the
connection timeout, the pool and parameter errors and the totality of `encode/2` were run through the public
functions with `mix run` scripts. The tests were not run by the author of this change (the owner of the
repository runs the suite); the integration test needs Core on 8181.

### After the hand-off

- **Old tests that pinned the bug.** Three `reader_test.exs` tests asserted the wrong
  FlatBuffer defaults: an absent `is_signed` as signed, an absent `bitWidth` as 32, and an
  absent `precision` as DOUBLE.
  - The two that the new unsigned and Float16 tests now cover are removed.
  - The `bitWidth` one now asserts Arrow's default of 0, which is no integer width, so the
    column has no type id.
- **A race in the new timeout tests.** The connect bound defaults to the call's `:timeout`, so
  against a silent peer the two bounds raced and gave `:connect_timeout` or `:timeout`
  depending on load. Each test now gives the connect a bound that never fires. The test that
  claimed the answer does not depend on the connect bound is removed, since it does.
- **A 30-second deadlock in a new test.** With `batch_size: 1` the writer flushes inside
  `write/2`'s call, so the test was blocked in `write/2` while the request waited for that
  same test to answer it. Each run waited out the 30-second receive timeout (the blocking
  mailbox of the review's F5). Its server now has an owner of its own that answers, and the
  test asserts the body and `total_writes: 1`. Each case takes milliseconds.
- **Docs drift (F13).**
  - `CLAUDE.md`'s module tree, patterns and dependencies now name Flight, gRPC, the
    supervisors, `StreamError` and `TestHelper`.
  - `Query.Flux`'s `:org` now says it defaults to the connection's.
  - `Query.SQLStream` lists `:timeout` and `:pool_timeout`.
  - `ConnectionSupervisor` says a connection has at most one writer.
  - The README's guide link works on GitHub.
  - `Client.HTTP` and `Flight.Client` are in HexDocs groups.
- **Gates,** each run one at a time:
  - Unit: 2,366 tests, run three times, in about 18 s; coverage 93.75%, and every changed line
    is covered. Format, both compile environments, credo, dialyzer and docs are clean.
  - Integration on fresh `influxdb:3.10.1-core` (`--memory 2g`) and 2.7, run twice each: Core
    746 tests, including the new Flight defaults and errors test; InfluxDB 2.7 90 tests.
    Auth-enabled Core tokens: 8 tests.
